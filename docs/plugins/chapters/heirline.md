# heirline.nvim

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

状态栏要显示：模式、文件名、Git 分支、诊断计数、光标位置、待闭合结构……
heirline 用声明式的组件树拼出状态栏，并且支持**点击交互**和弹出菜单。

这份配置对它做得比较深：状态栏不只是展示，还能点出菜单。

## 在当前配置里怎么用

### 状态栏内容

从左到右大致是：模式指示、文件信息、诊断计数、Git 分支、位置。
点击某些区域会打开菜单——这是配置自己实现的功能，不是 heirline 默认行为。

### 菜单的导航

打开状态栏菜单后：

| 按键 | 作用 |
|---|---|
| 方向键 / `j` `k` | 在菜单项间移动 |
| `Enter` | 执行 |
| `Esc` / `q` | 关闭 |

菜单打开时会**临时保存并替换**当前的 buffer 映射，关闭时还原。
所以打开菜单期间，普通按键可能被菜单接管——这是预期行为。

### 与 bufferline 的配合

状态栏在侧栏（neo-tree / aerial）里的偏移由 `config.sidebar_tabs` 统一处理，
所以侧栏顶部和编辑区顶部的标签行是对齐的。

## 动手练习

1. 观察状态栏各段内容，确认能看到模式、文件名、位置。
2. 点击 Git 分支区域，看是否弹出菜单。
3. 用 `j` / `k` 在菜单项间移动，`Esc` 关闭。
4. 关闭菜单后立刻按 `j`，确认它恢复成正常的向下移动（映射已还原）。
5. 进入可视模式，确认状态栏的模式指示变化。

**验收**：菜单能开能关，关闭后映射完全还原。

## 注意事项

- **菜单打开期间键位被接管**。这是它工作的方式，不是 bug。
- **状态栏内容依赖其它插件**：Git 分支来自 gitsigns/fugitive 类数据，
  诊断计数来自 Neovim 诊断系统。缺数据时对应段不显示。
- **修改状态栏要改组件树**，不是改一行字符串。
- 有专门的回归测试（`tests/statusline_menu_ui_spec.py`），改这块要先跑它。
