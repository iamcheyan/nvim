# dashboard-nvim

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

Neovim 直接启动是一片空缓冲区，你要先想起「今天要改哪个项目」再手动 `:cd`。
dashboard 把最近项目和最近文件摊在首屏，省掉这一步。

它只在**没有可恢复会话**时出现——Auto Session 有项目会话时优先恢复会话，
这符合「回到昨天的现场」比「重新挑文件」更常见的事实。

## 在当前配置里怎么用

Hyper 主题，两块内容：

| 区域 | 内容 | 上限 |
|---|---|---|
| Projects | 最近识别到的工作目录 | 8 个 |
| Recent files | 最近打开的文件（跨目录） | 10 个 |

选中项目不会直接打开文件，而是**调用 Snacks 文件搜索器并在该项目目录内查找**——
先选项目再选文件，避免在错误目录里搜不到想要的文件。

| 按键 | 作用 |
|---|---|
| `f` | 找文件 |
| `s` | 搜索文本 |
| `l` | 打开 Lazy 插件管理 |
| `:Dashboard` | 手动再次打开启动页 |

启动页的底部按钮默认已经改为上面三个；Helix 风格 preset 决定图标和间距。

## 动手练习

1. 先后打开三个不同项目的文件（比如 `~/development/cobol`、`~/nvim`、`~/wiki` 各一个）。
2. `:Dashboard` 再开一次启动页。
3. 在 Projects 里选 `~/nvim`，确认搜索器打开后路径在该项目内。
4. 回到 Recent files，选一个刚开过的文件，确认能直接进去。

**验收**：Projects 和 Recent files 都能命中你刚才的路径，且从 Projects 进入时
搜索范围被限制在该项目目录。

## 注意事项

- **刚安装时列表很短**。这两个列表来自 Neovim 的旧文件记录和会话记录，
  用几天才会积累起来；空列表不代表坏掉。
- **会话优先**。如果在某个项目里正常退出过，下次在这个目录启动会直接恢复会话，
  看不到 dashboard。想强制看首页就在别的目录启动，或先删掉会话。
- **Snacks 自带的 Dashboard 是关闭的**。启动页只有 dashboard-nvim 一处实现，
  改样式时不要去找 Snacks 的配置。
- 项目列表依赖自动识别的工作目录，如果你经常在 `$HOME` 下启动，列表价值不大；
  养成在项目目录启动的习惯。

## 查快捷键和帮助

```vim
:help dashboard
:verbose nmap <leader>ff     " 确认找文件最终绑在哪个插件
```

`:Dashboard` 可以反复调用，不会破坏当前缓冲区，只切换视图。
