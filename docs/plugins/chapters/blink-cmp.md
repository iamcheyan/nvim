# blink.cmp

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

插入模式需要补全：LSP 候选、路径、代码片段、当前缓冲区里的词。blink.cmp 把这四类
合成一个菜单，并且**不阻塞输入**——候选在后台算，你继续打字不受影响。

这份配置对它有明确的 COBOL 适配，这是它和其它语言最不一样的地方。

## 在当前配置里怎么用

### 基本操作

| 按键 | 作用 |
|---|---|
| 继续输入 | 候选实时过滤 |
| `<C-space>` | 手动打开候选菜单 |
| `<C-n>` / `<C-p>` | 下一个 / 上一个候选 |
| `<C-y>` | 接受当前候选 |
| `Enter` | 接受（**没有候选时保留原生 Enter 换行**） |
| `Tab` / `Shift-Tab` | 在候选与 snippet 占位符间移动 |
| `Esc` | 关闭菜单 |

### 候选来源

`lsp` → `path` → `snippets` → `buffer`，按这个优先级合并。
Lua 文件原本还有 `lazydev` 源，配置把它去掉了，改用标准 LSP 流程。

### COBOL 的三个特殊处理

这是配置里最有信息量的部分，因为它来自实际踩坑：

1. **句点不触发补全**。COBOL 用 `.` 结束句子，如果句点触发补全，
   每个语句结束都会弹出菜单。配置在 COBOL/CBL/COB 文件里把 `.` 加入
   `show_on_blocked_trigger_characters`。
2. **不自动补括号**。COBOL 的 `PERFORM 段落名` 是不带括号的调用，
   自动补 `()` 会直接造成语法错误。`auto_brackets.blocked_filetypes` 排除了三种 COBOL 扩展名。
3. **Tab 行为不同**。COBOL 固定格式对 Tab 有列对齐语义，配置对
   Tab 和补全字符做了专门处理。

> 换句话说：**同一个补全插件在 COBOL 里被刻意调得更「安静」**。
> 如果你在别的语言里觉得补全很主动，在 COBOL 里变得克制，那是设计。

## 动手练习

1. 打开一个 Lua 文件，输入 `vim.` 观察 LSP 候选。
2. 按 `<C-space>` 强制打开菜单，用 `<C-n>` / `<C-p>` 移动，`<C-y>` 接受。
3. 在插入模式输入一个路径片段（如 `./lu`），确认 path 源给出候选。
4. 打开一个 COBOL 文件，输入一条语句并以 `.` 结尾，
   确认**句点没有弹出菜单**。
5. 在 COBOL 里输入 `PERFORM `，确认没有自动补 `()`。

**验收**：前三条在 Lua 里成立，后两条在 COBOL 里成立——两种语言行为不同是预期的。

## 注意事项

- **`Enter` 的双重语义**。有候选时接受，没候选时换行。这个判断由插件做，
  但如果你装了别的回车相关插件，注意加载顺序。
- **COBOL 里补全更少是故意的**，不要为了「补全更积极」去解除上面三个限制。
- **补全不替代语法检查**。COBOL 的正确性最终看 `cobc`，补全只保证符号存在。
- **`kind_icons` 用 Nerd Font 等宽变体**。字体不对时图标会挤歪对齐。
- snippet 展开依赖 `vim.snippet.expand`；Neovim 版本太低会失效。
