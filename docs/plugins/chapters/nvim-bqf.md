# nvim-bqf

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

原生的 `:copen` 只是一个纯文本列表：没有语法高亮，看不出条目来自哪种语言；要判断一条搜索结果是否相关，只能先跳过去再跳回来。nvim-bqf 接管 `qf` 文件类型的窗口，加上语法高亮、按文件分组的上下文行，以及跟随光标移动的预览窗口。

搜索、`:vimgrep`、`:make`、LSP 引用等所有写入快速修复列表的操作都会受益，不需要改调用方。

## 在当前配置里怎么用

打开任意快速修复列表即可，插件在该缓冲区上自动生效：

```vim
:vimgrep /TODO/ **/*.md
:copen
```

| 按键 | 作用 |
|---|---|
| `<CR>` | 在当前窗口打开条目 |
| `o` | 打开条目并关闭快速修复窗口 |
| `O` | 以 drop 方式打开 |
| `<C-x>` / `<C-v>` | 水平 / 垂直分屏打开 |
| `t` / `T` | 新标签页 / 后台标签页打开 |
| `p` / `P` | 切换当前条目的预览 / 切换自动预览 |
| `zp` | 切换预览模式 |
| `<Tab>` / `<S-Tab>` | 展开 / 收起条目的上下文行 |
| `<C-n>` / `<C-p>` | 下一个 / 上一个文件 |
| `<` / `>` | 在快速修复历史之间切换 |

窗口高度会随条目数量调整（`auto_resize_height`），不会长期占满屏幕。

### 和 quicker.nvim 的分工

本配置同时安装了 quicker.nvim，它也挂在 `qf` 上，提供 `<`/`>` 展开上下文。两者共存时：bqf 负责高亮和预览，quicker 负责上下文展开与编辑。如果觉得预览重复，可以只保留其中一个；两者的快捷键互不覆盖，因为绑定在不同的动作上。

## 动手练习

1. 执行 `:vimgrep /TODO/ **/*.md`（没有结果时随便搜一个常见词）。
2. `:copen` 打开列表。
3. 确认条目按文件着色，右侧出现预览窗口。
4. 移动光标，确认预览跟随；按 `p` 关闭当前预览，再按 `P` 关掉自动预览。
5. 按 `<Tab>` 展开上下文，`<CR>` 跳到条目。

**验收**：`:set filetype?` 在快速修复窗口里是 `qf`，预览出现且能随光标更新；关闭预览后列表仍可正常跳转。

## 注意

- 只对快速修复窗口生效，`lopen` 打开的 location list 不会接管。
- 预览依赖文件名和行号；来自终端输出、没有文件路径的条目不会有预览。
