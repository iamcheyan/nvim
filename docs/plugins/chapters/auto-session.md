# auto-session

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

关掉终端再回来，窗口布局、打开的文件、当前目录全没了。auto-session 按**项目根目录**
保存这些状态，下次进入同一目录时恢复。

判断依据是当前工作目录，不是 Git 根——所以在一个大仓库的子目录里启动，
会认成另一个会话。

## 在当前配置里怎么用

| 按键 | 作用 |
|---|---|
| `<leader>ws` | 保存当前会话 |
| `<leader>wr` | 搜索并恢复会话 |
| `<leader>wa` | 切换自动保存 |
| `<leader>wd` | 删除会话 |

默认自动保存与自动恢复都开着，所以正常退出再进来不需要手动做任何事。

### 与启动页的关系

启动时如果找到了当前目录的会话，**直接恢复，不显示 dashboard**。
只有找不到会话时才显示启动页。这就是为什么有时看不到首页——不是配置坏了。

## 动手练习

1. 在某个项目里打开 3 个文件，分两个窗口（`:vsplit`）。
2. 在 Neovim 里 `:cd` 到一个**没有会话**的目录，再 `cd` 回来，观察是否恢复。
3. 退出 Neovim，在 shell 里 `cd` 到该项目目录重新启动，确认布局回来了。
4. `<leader>wd` 删掉该会话，重启确认变成 dashboard。

**验收**：布局（窗口分割 + 打开的文件 + 目录）能完整恢复；删除后不再恢复。

## 注意事项

- **会话记录本机路径**。不要让生成的 session 数据进公开仓库——
  它包含你的目录结构。配置仓库的 `.gitignore` 已经排除了状态目录。
- **恢复会话会覆盖启动参数**。`nvim somefile` 在会话存在时可能变成恢复后的布局，
  想强制只开一个文件用 `nvim --clean somefile` 或先删会话。
- **在 `$HOME` 启动会建一个巨大的会话**。养成在项目目录启动的习惯。
- **自动保存可能在你不想要的时候触发**。临时探索用 `<leader>wa` 关掉。
