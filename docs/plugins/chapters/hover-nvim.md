# hover.nvim

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

Neovim 自带的 `K` 只调用 LSP 的悬浮窗口，一次只能看一个来源：类型签名、诊断说明、命令手册，各自在不同的地方。hover.nvim 是这些来源之上的统一窗口：按同一个键，它依次询问已注册的来源，把第一个有内容的结果显示在同一个带边框的浮窗里。

在本配置里注册了四个来源：

| 来源 | 内容 |
|---|---|
| LSP | 类型、签名、文档注释 |
| 诊断 | 当前行的诊断详情（来自 LSP 或 linter） |
| man | `man` 手册页的摘要 |
| 词典 | 英文单词释义（依赖 `dictd` 或系统词典） |

## 在当前配置里怎么用

| 按键 | 作用 |
|---|---|
| `K` | 打开悬浮；按来源顺序取第一个有内容的结果 |
| `<leader>cH` | 先选择来源，再打开（多个来源都有内容时用） |

浮窗里按 `q` 关闭，普通滚动键可以翻页。

### 和其它悬浮的关系

noice.nvim 也自带 hover，本配置里已经关掉（`hover = { enabled = false }`），否则按一次 `K` 会同时出现两个窗口。

LSP 挂载时 `lua/plugins/lsp.lua` 会设置缓冲区内的 `K`。它调用的是 hover 的 `open()`；如果 hover 没有安装，则回退到 `vim.lsp.buf.hover()`，所以在没装这个插件的机器上 `K` 仍然能用。

### 版本说明

hover.nvim 的新版本要求 Neovim 0.11，并重写了来源注册方式。本配置固定在最后一个支持 Neovim 0.10 的提交上；升级 Neovim 之后可以去掉 `commit` 锁定，改用主线版本。

## 动手练习

1. 打开一个 LSP 已就绪的文件（例如 Python 或 Lua），等状态栏出现语言服务器名称。
2. 把光标放在一个函数名上，按 `K`。
3. 确认浮窗标题显示当前来源，内容是该函数的签名和文档。
4. 按 `q` 关闭，再按 `<leader>cH`，选择另一个来源。
5. 把光标放到有告警的行上，再按 `K`，确认能看到诊断说明。

**验收**：`K` 打开的是 hover 的浮窗而不是 Neovim 原生预览；没有 LSP 时 `:lua =vim.lsp.get_clients({bufnr=0})` 返回空列表，`K` 无内容属于预期。

## 注意

- 悬停内容来自 LSP，语言服务器没挂上时不会有结果，这不是插件故障。
- 词典来源需要系统安装词典服务；没装时该来源自动跳过，不影响其它来源。
