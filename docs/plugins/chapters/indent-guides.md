# 缩进参考线（snacks.nvim）

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

深层嵌套的代码靠缩进判断层级，缩进线把「这一行属于哪一层」画出来。
对 Python、YAML、Lua 这类缩进敏感的语言价值最大。

这里的缩进线由 **snacks.nvim** 提供，不是 `indent-blankline.nvim`：
snacks 已经在本配置里负责搜索、通知和工具，缩进线复用同一个插件，
避免两套缩进绘制互相覆盖。

## 在当前配置里怎么用

编辑器打开时缩进参考线保持显示；当前没有单独的快捷键开关。配置里
`animate.enabled = false`：关闭动画，保证打字和移动没有延迟。

### 与 hlchunk 的分工

`hlchunk.nvim` 画的是**光标所在代码块**的边界，缩进线画的是**所有层级**。
两者叠加会显得很乱，所以 hlchunk 只启用 `chunk`，缩进线交给 snacks。

### 与 COBOL 的关系

COBOL 固定格式**不靠缩进表达结构**，靠列位置。所以在 COBOL buffer 里
缩进线意义不大，改由 `cobol.nvim` 画列标尺。这是两类完全不同的视觉辅助。

## 动手练习

1. 打开一个多层嵌套的 Lua 或 Python 文件，观察缩进线。
2. 检查打开文件时缩进参考线保持显示。
3. 打开一个 COBOL 文件，确认显示的是**列标尺**而不是缩进线。
4. 在一个只有单层缩进的文件里确认不会画出多余线条。

**验收**：缩进参考线正常显示；COBOL 文件不画通用缩进线。

## 注意

- 文档里如果看到 `indent-blankline.nvim` 这个名字，指的是历史方案；现在的实现是 snacks.nvim。
- 缩进线是虚拟文本，不写入文件。
