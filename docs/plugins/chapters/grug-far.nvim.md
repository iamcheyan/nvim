# grug-far.nvim

> 公开插件 · [回到插件目录](../PLUGINS.md)

## 它解决什么问题

「把这个函数名在项目里全部改掉」这种活，用 `:s` 只能一个文件一个缓冲区地做。
grug-far 提供一个搜索替换面板：搜索词、替换词、文件过滤、实时匹配数，
确认后再落盘。

**它真的会改文件**，所以配置把「先看匹配数」当成主要安全阀。

## 在当前配置里怎么用

| 按键 | 作用 |
|---|---|
| `<leader>sr` | 打开项目搜索替换，并按当前文件扩展名预填 Files Filter（`*.lua` 这一类）。无扩展名或特殊缓冲不预填。键只在 `keymaps.lua` |
| `<leader>sR` | 限定当前文件 |
| 选中文字后 `<leader>sr` | 把选中文字带入搜索框 |

面板里三个字段：

| 字段 | 说明 |
|---|---|
| Search | 搜索模式（支持正则） |
| Replace | 替换内容 |
| Files Filter | 文件过滤，例如 `*.cob`、`src/**/*.lua` |

面板顶部会显示 `matches in N files`。**这个数字是决定是否执行的唯一依据**：
数字不对说明过滤条件不够严，先改过滤再看，不要直接执行。

### 执行与撤销

执行替换后是先写入工作树，再由你自己 `git diff` 检查。
如果改错了，用 Git 回退，grug-far 不提供自己的 undo 栈。

## 动手练习

1. 打开本仓库，`<leader>sr`。
2. Search 填一个你确定只出现在少数文件里的词（比如某个函数名）。
3. 看顶部的匹配数，把 Files Filter 改成 `lua/**/*.lua`，确认数字变小。
4. 在 Visual 模式选中一个词，按 `<leader>sr`，确认搜索框被预填。
5. 不要执行替换，按 `Esc` 关闭，然后 `git status` 确认工作树干净。

**验收**：能通过过滤条件把匹配数压到预期范围，且未确认前不产生任何写入。

## 注意事项

- **匹配数是安全阀，不是装饰**。几百个匹配通常意味着过滤太宽。
- **正则语法**是 ripgrep 的语法，不是 Vim 的 `\v` 风格。写 `\d+` 而不是 `\v\d+`。
- **二进制和大文件被跳过**，这是 ripgrep 的行为，不是插件丢失。
- **替换后没有内置撤销**。养成先看 `git status` 再执行的顺序。
- `<leader>s` 前缀下还有别的键（搜索相关），`<leader>sr` 是替换，
  不要把它和 `Ctrl-d`（多光标跳过匹配）搞混。
