# Neovim 架构：buffer、window、tab

> 这三个词经常被混用。它们的层次关系决定了「关掉窗口为什么文件还在」。

## 三层结构

```
tab page（一个布局）
 └── window（一个视口）× N
      └── buffer（一个文件的内存副本）× 1
```

反过来看更清楚：

- 一个 **buffer** 可以被多个 window 同时显示
- 一个 **window** 同一时刻只显示一个 buffer
- 一个 **tab page** 包含一个或多个 window

## buffer

buffer 是文件在内存里的副本。打开文件 = 读进 buffer；编辑 = 改 buffer；
`:w` = 把 buffer 写回磁盘。

关键性质：

- **buffer 有编号**，`:ls` 能看到
- **buffer 有名字**（文件路径），也可以无名
- **buffer 可以被隐藏**：不在任何窗口显示，但仍在内存里，修改保留
- **`:bd` 才真正关闭**，`:q` 只关窗口

这就是「关掉窗口后 `:ls` 还能看到那个文件」的原因。

### buffer 的状态

`:ls` 输出里每行开头有标记：

| 标记 | 含义 |
|---|---|
| `a` | active，正在某个窗口显示 |
| `h` | hidden，加载但没显示 |
| `%` | 当前窗口的 buffer |
| `#` | 上一个访问过的 |
| `+` | 有未保存修改 |
| `-` | 不可修改（`nomodifiable`） |

## window

window 是一个「看 buffer 的矩形区域」。

关键性质：

- 每个 window 有自己的**光标位置**、滚动位置、折叠状态
- 同一个 buffer 在两个 window 里，光标的联动取决于 `scrollbind`（默认不联动）
- window 是 **tab page 内**的概念，`:sp` / `:vs` 分割的是当前 tab

`:help windows` 讲全了。

## tab page

tab page 是一组 window 的**布局**。

**它不是文件标签栏。** 这是最常见的误解。

正确的用法：

- 一个 tab 放「写代码」的布局（左文件树、右代码、下终端）
- 另一个 tab 放「看文档」的布局（左右分屏两份文档）

错误的用法：

- 每个文件开一个 tab（应该用 buffer）

想要文件标签栏的外观，用 bufferline 插件——它显示 buffer 列表，样式像标签栏。

## 为什么这样设计

因为这个模型允许**同一个文件在不同上下文里同时可见**。

比如改一个函数：上面窗口看函数定义，下面窗口看调用处。两个窗口，一个 buffer——
改任一处，两边同时更新，因为它们是同一块内存。

用「标签页」模型的编辑器做不到这点（要么同一文件开两份，要么来回切）。

## 实用推论

**1. 关窗口 ≠ 丢文件**

`:q` 关窗口，文件还在 buffer 里。`:ls` 能看到，`:b 名字` 能切回来。

**2. 缓冲区列表有一百个是正常的**

一天开几十个文件，buffer 累积很正常。定期 `:bd` 清理，或者重启。

**3. 会话保存的是布局 + buffer 列表**

`<leader>ws` 保存的会话同时记录「哪些 buffer 打开着」和「窗口怎么分的」。

**4. 有些键是 buffer 局部的**

LSP、gitsigns 的键在特定 buffer 里才存在。这解释了为什么同一个 `gd` 在不同文件里行为不同。

## 常见困惑对照

| 现象 | 原因 |
|---|---|
| 关掉窗口后文件还在 `:ls` 里 | window 关了，buffer 没关 |
| `:q` 拒绝退出 | 有 buffer 有未保存修改（用 `:q!` 或先 `:w`） |
| 两个窗口改同一文件互相影响 | 同一个 buffer，这是对的 |
| 一个文件在两个窗口光标不同步 | window 各有自己的光标 |
| `:tabnew` 开一堆，切起来乱 | 该用 buffer，不是 tab |
