# 输入法与中文处理

> 在 Vim 里打中文会遇到模式切换的摩擦。这一篇讲怎么减少它。

## 核心矛盾

Vim 是模式编辑器：普通模式按键是命令，插入模式才是文字。

中文输入法也有模式：中文 / 英文。

两套模式叠加，就出现了「我想按 `Esc` 退出插入，结果输入法还开着」这类问题。

## 最常见的三个卡点

**1. 在普通模式输入法还开着**

按 `j` 想往下移，结果输入法弹出候选框。

**2. 输入法拦截了 `Esc`**

按 `Esc` 想回普通模式，输入法把它吃掉（用于取消候选）。

**3. 全角标点**

在中文输入法下打 `:` `,` `(` 会得到全角的 `：` `，` `（`，命令就不生效了。

## 处理办法

### 办法一：输入法自动切换（推荐）

有些方案能让输入法跟随 Vim 模式自动切换：

| 平台 / 环境 | 方案 |
|---|---|
| macOS | 用 Hammerspoon 或输入法自带的应用切换 |
| Linux (fcitx5) | `fcitx5` 的 vim 模式插件 |
| Linux (ibus) | `ibus` 的 vim 模式 |
| Windows | 输入法自带英文模式，手动切 |

原理：Neovim 进入插入模式时通知输入法切英文，离开时切回中文。
**具体能不能做取决于输入法和终端**，不是 Neovim 配置能完全解决的。

### 办法二：接受切换，练成肌肉记忆

很多长期用 Vim 的人就是这样：

- `i` 之前切中文
- `Esc` 之前切英文

听起来麻烦，但切换键（通常是 `Shift` 或 `Ctrl-Space`）会变成条件反射。

这份配置里也有个相关的辅助：Caps Lock 状态指示器，见
[指南：Caps Lock](../guides/caps-lock.html)。

### 办法三：用 `Ctrl-^` 而不是 `Esc`

某些终端和输入法组合下，`Ctrl-[`（等价于 `Esc`）不会被输入法吃掉。

Vim 里 `Ctrl-[` 就是 `Esc`。可以试试哪个在你环境里更可靠。

## 全角标点

在中文输入法下按 `:` 得到的是 `：`（全角），命令行不认。

**检查方法**：`:set fileencoding?` 能执行说明是半角；报错说明是全角。

预防：

- 进命令行前切英文
- 或者用 `q:` 历史窗口，从里面复制半角命令

## COBOL 里的中文

COBOL 固定格式对列有严格要求，中文字符是**多字节**的，会破坏列对齐。

这份配置的处理：

```lua
-- 遇到底层：smart_tab、smart_comments、列标尺都按字节算
```

所以 COBOL 源文件里的中文注释：

- 只能放在第 7 列的 `*` 注释行
- 或者字符串字面量里
- **不能用来对齐列**，因为一个字占 3 字节（UTF-8）

课程里的 COBOL 注释全是日文或中文，但都放在 `*` 行，不参与列对齐。

## 文件名里的中文

现代 Linux 用 UTF-8 文件名，一般没问题。

如果遇到：`:e` 时文件名显示成 `?`，检查 `LANG` 环境变量：

```sh
echo $LANG
# 应该是 xxx.UTF-8
```

## 这份配置的相关部分

| 部分 | 作用 |
|---|---|
| `termsync` | 终端同步，减少中文渲染错位 |
| `ambiwidth=double` | 把「歧义宽度」字符按双宽显示 |
| 字体 | 需要中文字体，否则方块 |

`ambiwidth` 值得说：某些符号（`○` `□` `※`）在不同终端里宽度不一致，
设成 `double` 让 Neovim 统一按两列算，对齐才准。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `j` `k` 没反应 | 输入法还在中文模式 | 切英文 |
| `Esc` 退不出插入 | 输入法拦截 | 试 `Ctrl-[` |
| 命令行报错但看不出错 | 全角标点 | 切英文重打 |
| 中文显示成方块 | 字体没有中文字形 | 装中文字体 |
| 中文占位宽度不对 | `ambiwidth` 设置 | 试 `single` / `double` |
| 状态栏中文错位 | 字体非等宽 | 用等宽字体 |

## 一个务实的建议

**别为了输入法去改一堆配置。** 大部分摩擦会随着熟练消失。

真正需要解决的是「`Esc` 被吃掉」——这个影响最大。先确认你的终端 + 输入法组合下
`Esc` 和 `Ctrl-[` 哪个可靠，固定用那个。
