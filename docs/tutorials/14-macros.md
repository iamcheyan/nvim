# 14 宏与重复

> `.` 只能重复一个操作。要重复一串操作，用宏。

## 宏是什么

宏就是「录下我按的一串键，然后可以重放」。

| 步骤 | 按键 |
|---|---|
| 开始录到寄存器 a | `qa` |
| 做你的操作 | ... |
| 停止录制 | `q` |
| 重放一次 | `@a` |
| 重放 N 次 | `10@a` |
| 重放上一次的宏 | `@@` |

## 第一个宏

目标：给 5 行都加上行尾分号。

```
qa         开始录到 a
A;         行尾追加分号
Esc        退回普通模式
j          下一行
q          停止
5@a        重放 5 次
```

**关键点**：宏里包含 `j`（移动到下一行），所以重放时会自动往下走。

## 写宏的规矩

**1. 用 `q` 结尾，不要在插入模式里停**

宏录制会记录「回到普通模式」这个动作。最后按 `Esc` 再用 `q` 结束。

**2. 起始和结束位置要「可循环」**

如果宏的结尾让光标停在下一行的开头，重放时就能连续工作。

上面的例子里，`j` 让光标下移，所以 `5@a` 会一行一行处理下去。

**3. 先在一个样本上试，再批量**

```
qa ... q      录
@a            试一次，看对不对
u             不对就撤销
10@a          对了才批量
```

## 用命名寄存器

宏存在寄存器里，和 `"a` 到 `"z` 共用：

```
qa ... q      录到 a
qb ... q      录到 b
@a @b         分别重放
```

注意：录制会**覆盖**该寄存器原来的内容。

## 给宏追加操作

想把宏加长：

```
qA ... q      大写 A = 追加到 a 寄存器末尾
```

## 一个真实场景

把这段：

```
foo_id
foo_name
foo_value
```

改成：

```
foo_id = None
foo_name = None
foo_value = None
```

宏：

```
qa            开始
A = None     行尾加内容
Esc           退出插入
j             下一行
q             停止
2@a           重放两次
```

## 宏与可视模式

也可以对选中的多行重放：

```
V 选中多行
:normal @a
```

`normal @a` 会对每一行执行一次宏。

## 递归宏

宏里调用自己，可以用计数控制次数：

```
qa
...操作...
@a        在宏里调用自己（需要 q 前把 @a 去掉避免无限递归）
q
```

这个技巧比较危险，容易无限循环。要中断按 `Ctrl-c`。

**更安全的做法**：不要在宏里写 `@a`，改用计数 `100@a`，遇到错误会停下。

## 宏的重放技巧

| 写法 | 说明 |
|---|---|
| `@a` | 重放 a |
| `@@` | 重放上次的宏 |
| `5@a` | 重放 5 次 |
| `@: ` | 重放上次的 Ex 命令 |
| `.` | 重放上次的修改（不含移动） |

## 宏 vs `.` vs `:g`

怎么选：

| 场景 | 用什么 |
|---|---|
| 一个简单修改，重复多次 | `.` |
| 一串操作，每行都要做 | 宏 |
| 按模式选择行，做同一件事 | `:g/模式/normal ...` |
| 跨文件 | grug-far |

`:g` 配合 `normal` 往往比宏更可控，因为它能明确指定「哪些行」：

```vim
:g/^item_/normal! A = None
```

## 调试宏

宏出问题时：

1. `:reg a` 看 a 寄存器里到底录了什么
2. 在里面找多余的按键（比如忘了 `Esc` 导致后面的键被当文字输入）
3. 重新录

**`:reg a` 是排查宏的第一站。**

## 练习

1. 准备 5 行文字，录一个宏给每行末尾加 `;`
2. `@a` 试一次，`u` 撤销
3. `5@a` 批量执行
4. `:reg a` 看宏内容
5. 用 `:g/^/normal! A!` 给所有行加 `!`，对比和宏的差别
6. 录一个宏，把每行的第一个词转成大写（提示：`gUiw` + `j`）

**验收**：能录一个可循环的宏，并用 `:reg` 检查它。
