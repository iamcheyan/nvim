# 01 它是从哪来的：ed → vi → Vim → Neovim

> 想理解 Vim 为什么长这样，得先知道它从哪儿来。这一篇讲完整的一条线：从 1969 年的一台 PDP-7，到今天你正在用的 Neovim。

## 1969：ed 诞生，因为要有个编辑器

Unix 最初只有三样东西：**汇编器、编辑器和 shell**。1969 年 8 月，Ken Thompson 在 AT&T 贝尔实验室的一台 PDP-7 上写出了 **ed**。

ed 是**行编辑器**。它没有全屏界面——你面对的不是一幅文本画面，而是一行提示符。想看内容就输入 `p` 打印某几行，想改就打命令改第几行。

为什么长这样？因为当时的设备是**电传打字机**（teletype）：一台打字机连着主机，你敲一行，它打一行在纸上。纸上印过的东西改不了，所以「屏幕编辑」这个概念根本不成立。

ed 非常难用。同期的 George Coulouris 评价说，ed 那些隐晦的命令只适合「**不死之身**」——普通人记不住。

但 ed 有两个东西留下来了：

**1. 正则表达式。** Thompson 之前在 qed 上做过正则，ed 也实现了。

**2. `g/re/p` 这个命令**——对匹配某模式的所有行执行操作。后来有人把「全局搜索并打印」单独抽出来，就是 **grep**。

> 也就是说，你天天用的 `grep`，名字来自 ed 里的一条命令。

## 1976：em，「给凡人用的编辑器」

Coulouris 决定改进 ed。1976 年 2 月，他在玛丽女王学院教书时，基于 Thompson 的 ed 源码做了 **em**（editor for mortals，凡人编辑器）。

em 的关键突破：它是 Unix 上最早大量使用「**原始终端输入模式**」的程序之一——按键不再由终端驱动处理，而是交给程序自己，这才可能做出实时响应的界面。

那年夏天 Coulouris 去 UC 伯克利访问，带了一卷装着 em 的磁带给人看。有人觉得这种编辑器太耗资源，但**有个人很感兴趣，他叫 Bill Joy**。

## 1976–1979：从 ex 到 vi

Bill Joy 和 Chuck Haley 是伯克利的两个研究生。他们受 em 启发，从 em 拿代码做了 **en**，再把 en 扩展成 **ex**（version 0.1）。

Haley 离开后，另一个人 Bruce Englar 劝 Joy 重新设计。**1977 年 6 月到 10 月**，Joy 给 ex 加上了**全屏可视模式**——这就是 vi。

关键的一点：**vi 和 ex 是同一个程序，不是两个。**

- `ex` 启动，进入行编辑模式
- `vi` 启动，直接进入可视模式

`vi` 这个名字，就是 ex 里「进入可视模式」那条命令的缩写（完整写法是 `visual`）。

Joy 后来在访谈里很坦率地说，全屏编辑的想法是**从 Xerox PARC 的 Bravo 编辑器手册里「偷」来的**——他偷偷看了那份手册然后照做。`.`（重复上次操作）也是从 Bravo 来的。

### 为什么是 Esc、h、j、k、l

这是整个 Vim 历史里最值得知道的一段。

Joy 用的终端是 **Lear Siegler ADM-3A**。这台机器上：

- **Esc 键就在今天 Tab 键的位置**——左手小指自然落点，切换模式很方便
- **h j k l 四个键上直接印着箭头**，因为这台终端没有独立的方向键

所以 vi 用 `hjkl` 移动、用 `Esc` 切换模式，**不是精心设计的结果，是那台键盘长这样**。

还有一点：单字符命令、以及「输入快于显示」的能力，是在 300 波特（约 30 字符/秒）的调制解调器速度下逼出来的——命令越短越好。

**1978 年 3 月**，ex 1.1 随第一版 BSD Unix 发布。**1979 年 5 月**，ex 2.0 随 Second BSD 发布，这个版本才正式以 `vi` 的名字安装。

## 1980s–1990s：vi 遍地开花，也遍地分裂

vi 随 Unix 传播开，但各家的实现开始分叉。商业 Unix 各有各的 vi，互相不兼容。

同时出现了一批**免费的克隆**：

| 克隆 | 特点 |
|---|---|
| **elvis** | 能读 HTML、manpage、TeX |
| **nvi** | 最忠实于原始 vi |
| **vile** | 有 emacs 的味道 |
| **Stevie** | Tony Andrews 等人做的 vi 克隆 |

**1991 年**，POSIX 把 vi 的行为标准化了——但只标准化了「可移植子集」，也就是最基础的那部分。

> 顺便说：台湾那本 2000 年的《大家來學VIM》里花了很大篇幅比较 elvis、nvi、vile。今天这三个基本没人用了，只有 Vim 和 Neovim 活了下来。

## 1988–1991：Bram Moolenaar 和 Vim

**1988 年**，荷兰人 Bram Moolenaar 开始做自己的编辑器。他的起点是 **Stevie 移植到 Amiga 上的版本**。

**1991 年 11 月 2 日**，version 1.14 完成，这是第一个公开发布版。**1992 年 1 月**通过 Fish Disk #591 分发。

名字最初解释为 **Vi IMitation**（vi 的模仿）。但功能越加越多，超越了「克隆」的范围，于是改成了 **Vi IMproved**（vi 的改进版）。

Vim 加了什么：

- 语法高亮（可脚本化）
- 鼠标支持
- 图形界面（gVim）
- **可视化选择模式**（visual mode，vi 只有「可视模式」这一个说法）
- 大量新的编辑命令
- 自己的脚本语言 VimScript
- 内置帮助系统 `:help`

Vim 还有一个 **vi 兼容模式**，能退回到接近 vi 的行为。但它也丢了一些 vi 的东西，比如 open mode。

### Charityware

Vim 的许可里有一条特别的：**鼓励使用者给乌干达的儿童捐款**。Moolenaar 本人在乌干达做过志愿工作，这跟他早年在荷兰的教会背景有关。

所以 Vim 是「慈善软件」（charityware），不是普通意义上的自由软件。

## 2014：Neovim 分叉

到 2010 年代，Vim 的代码库积累了大量历史包袱：

- 单线程，插件跑起来会阻塞界面
- VimScript 写复杂配置很痛苦
- 代码结构难以维护

有人提交了给 Vim 加多线程支持的补丁，**被拒绝了**。

**2014 年**，巴西开发者 **Thiago de Arruda** 发起了 **Neovim**——不是替换 Vim，而是把 Vim 的代码库重构一遍。他把这个目标叫做「**Vim 在 21 世纪的重生**」。

2014 年 3 月，项目众筹成功，能支持至少一名全职开发者。

Neovim 带来的技术变化：

| 变化 | 意义 |
|---|---|
| 用 **libuv** 做异步 I/O | 插件不再阻塞界面 |
| 内置 **终端模拟器** | 不用切出去开终端 |
| 内置 **LSP 客户端** | 不用装一堆插件 |
| 内置 **Treesitter** | 语法解析现代化 |
| **Lua** 作为一等脚本语言 | 配置写起来清爽得多 |
| 支持 headless / 批处理 | 能做 CI、能跑脚本 |

**2021 年 7 月 2 日**，Neovim 0.5 发布，LSP、Treesitter、完整 Lua 支持同时到位。这一版之后，NvChad、LazyVim 这类配置框架开始大量出现。

Vim 的 VimScript 仍然被支持（为了兼容老配置），但 **Vim9script 不会被支持**——Neovim 的精力全放在 Lua 上。

### 今天的位置

- **2025 年**，Stack Overflow 开发者调查里，Neovim 连续第五年被评为最受推崇的开发环境
- **2026 年 8 月**，Neovim 在 GitHub 上约 **10.2 万**星，Vim 约 **4 万**

## 这条线意味着什么

把演化串起来看，会发现 Vim 的每一个「奇怪之处」都有具体来源：

| 你可能觉得奇怪 | 实际原因 |
|---|---|
| 为什么要按 `Esc` 切模式 | ADM-3A 的 Esc 在 Tab 位置，好按 |
| 为什么用 `hjkl` 移动 | 那台终端的方向键就印在这四个键上 |
| 为什么命令都是单字母 | 300 波特的网速下，越短越好 |
| 为什么有 ed 风格的 `:s` 命令 | 它是行编辑器 ex 的遗产 |
| 为什么 `grep` 和 Vim 有点像 | 都来自 ed 的 `g/re/p` |
| 为什么 `visual` 模式叫 visual | 就是 ex 里那条命令的名字 |

**它不是被设计成这样的，是被当年的硬件和网络逼成这样的。**

理解这一点，后面学按键时就不会觉得「为什么这么反人类」——它针对的是四十多年前的设备，而那套操作方式在今天的键盘上依然高效，这才是它活下来的原因。
